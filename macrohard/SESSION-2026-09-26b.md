## Gefundene und behobene Anwendungsfehler

Alle vier über Browser-Interaktion gefunden, nicht über Code-Lesen.

### 1. Kalender ab dem zweiten Öffnen komplett tot

`viewYear`, `viewMonth` und `selectedDay` waren funktionslokale `let`-Variablen in
`buildCalendar()`. Der `CALENDAR_INITIALIZED`-Zweig ruft `renderCalendar()` auf, bevor
diese Deklarationen ausgewertet sind:

```
ReferenceError: Cannot access 'viewMonth' before initialization
```

Das Fenster blieb leer. Ab dem zweiten Öffnen war der Kalender unbrauchbar.

**Fix:** State liegt in `calState` auf IIFE-Ebene. `buildCalendar()` setzt
`calState.body` bei **jedem** Öffnen neu, damit ein wiedergeöffneter Kalender nicht in
das gelöste Fenster des ersten rendert.

**Verifiziert:** 5× öffnen/schließen ohne Fehler, 42 Tage, Monatsnavigation,
Tagesauswahl. Test: 0/5 vor dem Fix, 5/5 danach.

### 2. Tic-Tac-Toe: `ReferenceError: toast is not defined`

`buildGame`, `buildCalendar`, `buildNotes` und die anderen liegen hinter dem `})();` der
Haupt-IIFE. Sie rufen `toast()` auf, das nur innerhalb der IIFE existierte — exportiert
war nur `window.openApp`. Der 4×4-Schalter warf:

```
ReferenceError: toast is not defined
```

**Fix:** `window.toast = toast` am IIFE-Ende.

**Anmerkung:** `no-undef` hatte diese Stelle vorher als Lint-Artefakt abgetan. Der
generische AST-Test prüft jetzt alle IIFE-Helfer, die von außen referenziert werden, und
meldet auf dem alten Code genau `toast`.

### 3. Music: `TypeError: Cannot set properties of undefined`

Der Shuffle-Handler setzte in einem `setTimeout(function(){})` seinen eigenen
Highlight zurück. Dort ist `this` das globale Objekt, `this.style` ist `undefined`:

```
TypeError: Cannot set properties of undefined (setting 'background')
```

**Fix:** Button in `const btn` fangen. Der Test sucht alle `this`-Zugriffe in
Plain-Function-Timer-Callbacks und zeigt auf Zeile 5388 des alten Codes.

### 4. Escape schloss nie ein Fenster

Der Esc-Handler tat:

```js
if (focused && focused._escClose) focused._escClose();
```

`focused` ist aber durchgehend ein **App-ID-String** (`focused = id` bei jedem Open,
Focus und Taskbar-Klick). Ein String hat keine `_escClose`-Eigenschaft. Die Bedingung war
immer falsch, Escape tat nichts.

**Fix:** Escape klickt den `.wclose`-Button des fokussierten Fensters — damit laufen
auch Interval-Cleanup und die Init-Flag-Resets. Fallback: oberstes Fenster per z-index.

## Wiederbelebte Features

### Session-Restore existierte nicht

`restoreSession()` war vollständig geschrieben und wurde **nirgends aufgerufen**.
`saveSession()` lief bei jedem Open, Close und Drag, also füllte sich `os_session` in
localStorage und niemand las es zurück. Ein Reload kam immer mit leerem Desktop — genau
das, was README und Skill dokumentieren.

Drei Defekte im alten Body mussten mit behoben werden, sonst hätte die Verdrahtung
nichts gebracht:

| Defekt | Folge |
|---|---|
| `if (!s.visible) return;` | Minimierte Fenster werden als `visible:false` gespeichert und wären beim Restore **verschwunden** statt minimiert zurückzukommen |
| Icon-Lookup als `tb-<id>` | Mehrfachinstanz-Apps (Notepad, Terminal, Editor) haben ein `-inst-N`-Suffix, das Icon wurde nie aktualisiert |
| Whitelist über `apps`-Objekt | Das Objekt ist deklariert und **nie befüllt** — der Filter hätte jedes Fenster verworfen |

**Fix:** Aufruf nach dem Ausblenden des Locks, über zwei Pfade (Boot-Timer bei 4,2 s und
Lock-Klick, weil der Klick den Timer überspringt), idempotent über `sessionRestored`.
Whitelist liest jetzt `knownAppIds()` aus den Desktop-Icons. `saveSession()` speichert
zusätzlich das `minimized`-Flag.

**Verifiziert:** über echten Reload, 5 Fenster mit exakten Positionen, Paint minimiert
mit gedimmtem Icon, Notepad-Icon unter `tb-notepad-inst-1`. Robustheit: korruptes JSON,
leeres Array, unbekannte IDs, `__proto__` und `constructor`, fehlende Felder — alles ohne
Absturz. Zweimaliger Restore dupliziert nichts.

### Calculator: `#cCur` war totes Element

`calcPress('C')` schrieb `"0"` hinein, `calcPress('=')` leerte es, dazwischen wurde es
nie berührt. Das Element existierte nur, um wie ein zweites Display auszusehen.

**Fix:** `calcPreview()` zeigt das laufende Ergebnis, während getippt wird.

| Eingabe | Live |
|---|---|
| `7×` | 7 |
| `7×8` | 56 |
| `2+3×4` | 14 (Priorität, nicht links→rechts) |
| `12+3×(` | 15 (längster auswertbarer Präfix) |
| `(1+2)×3` | 9 |
| `123÷4÷` | 30.75 |
| `50%` | 0.5 |

Beide Eingabepfade aktualisieren: Bildschirmtasten über `calcPress`, Ziffern und Backspace
direkt über `calcPreview`, weil sie selbst ins Input schreiben.

## Methodische Lehren

### 1. Grüne Tests haben vier Live-Bugs nicht gesehen

172/172 grün, vier echte Fehler. Die Testsuite prüfte überwiegend Textmuster
(`flat.includes(...)`) statt Verhalten. Jeder der vier Bugs wäre durch einen
Verhaltenstest aufgetaucht.

### 2. `no-undef` war wieder kein Fehlalarm

Zweite Session in Folge. Die Lint-Warnung zu `toast` habe ich in der vorigen Session
noch als „im Browser verifiziert existent" abgetan. Sie war falsch — für die Apps
außerhalb der IIFE existierte `toast` nicht.

### 3. Tests, die exakte Formate matchen, brechen bei jedem Refactor

Drei bestehende Tests mussten heute umgeschrieben werden, weil sie an Code-Formen klebten:

| Test | Problem |
|---|---|
| `close-buttons-regression` | schnitt die Datei an der ersten `.wclose`-Fundstelle ab — nach dem Esc-Fix ist das der Escape-Pfad |
| `hardening-regression` | prüfte auf `function loadEvents()`, die Kalender-Helfer heißen jetzt `calLoadEvents` |
| `module-boundary` | pinnte `?v=63` und wurde bei jedem Cache-Buster-Bump rot |

Lehre: Identifier und Verhalten prüfen, nicht Formatierung.

### 4. Der Cache-Buster hätte die Live-Fixes verschluckt

Nach dem ersten Push war die Live-Datei inhaltlich aktuell, aber `index.html` zeigte auf
`app.js?v=63` — dieselbe URL, die der Service Worker gecacht hatte. Besucher hätten die
alte Datei bekommen. Nur weil `last-modified` im `curl -I` **älter** war als der Commit,
ist es aufgefallen. Diese Prüfung gehört ab jetzt vor jeden Push.

### 5. Ein Test kann grün sein und nichts prüfen

Der generische IIFE-Export-Test lief zunächst gegen den alten Code **grün** — die
Tiefenzählung für Top-Level-Funktionen zählte die öffnende Klammer der IIFE mit, `inside`
war fast leer, die Kandidatenmenge leer, die Assertion trivially wahr.

Erst eine explizite Anti-Vakuum-Assertion (`candidates.length >= 2`,
`candidates.includes('toast')`) machte das sichtbar. Danach: 4/6 gegen alt, 6/6 nach dem
Fix. Ein grüner Test ist kein Beleg, ein **neu hinzugefügter** grüner Test schon gar nicht.

### 6. Regex-Literale und Kommentare zerlegen jeden handgebauten Parser

Drei Fehlversuche beim AST-Testen, alle aus handgeschriebenem Tiefenzählen:

- Regex-Literale enthalten geschweifte Klammern → Tiefenzähler desynchronisierte und
  „fand" eine Funktion namens `t` aus einem Regex
- rekursives `walk()` im Callback re-entrant → Knoten fielen stillschweigend weg
- `addEventListener` hat den Listener in `arguments[1]`, nicht `[0]` → 0 Treffer bei
  285 Aufrufen

`espree` liegt als ESLint-Dependency im Repo. Ab jetzt für AST-Aussagen benutzen statt
Regex auf Quelltext.

### 7. Meine eigenen Messfehler als vermeintliche Bugs

Zweimal habe ich ein funktionierendes Feature für kaputt gehalten:

- Taskbar-Restore: hatte vorher das Fenster geschlossen, der Icon gehörte zu einem
  anderen. Korrekt getestet: minimize → restore → minimize → restore läuft
- Calculator `1+`: zeigte `1` statt „leer" — richtig ist `1`, der Operator wartet und
  links steht das Ergebnis. Meine Erwartungsliste war inkonsistent, nicht der Code
